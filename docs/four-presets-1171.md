# 4개 프리셋과 1.17.1 지원 작업 상태

## 구현한 부분

- 기존 C++ 코어의 프리셋 범위를 1~4로 확장했다.
- Windows 입력 어댑터를 F1~F4 저장, 숫자 1~4 불러오기로 변경했다.
- 원본 Loadout Manager에서 같은 8개 동작을 지정하는 JSON을 만들었다.
- 읽기 전용 1.17.1 진단 도구와 해당 도구의 별도 Windows EXE를 만들었다.

원본 기능 전체를 새 프로그램으로 재구현한 것은 아니다. 원본의 GUI, 능력치·마법,
아이템, 컨트롤러, 프로필, 방사형 메뉴 등의 기능은 사용자가 제공한 원본 EXE를
계속 사용해야 한다. 키 설정은 그 원본에 적용할 수 있다. 이 구성을 독립적인 새 모드의
완성으로 설명하지 않는다.

막혀 있었지만 Git HTTPS 경로는 사용할 수 있었다.

- 저장소: https://github.com/The-Grand-Archives/Elden-Ring-CT-TGA
- 확인 커밋: `7926205c5a2ed236dd31278c4f5579c964ceec35`
- CHANGELOG: v1.19.1 (2026-09-08), App Ver. 1.17.1 지원 명시

  `Hero/EquipMagicData` XML 필드 위치를 진단에 참고했다.

이 자료는 읽기 주소의 근거이며 우리 도구의 실제 게임 검증을 대신하지 않는다.
첨부된 구형 JSON의 고정 주소를 1.17.1에 맞는다고 추측해서 덮어쓰지 않았다.
원본의 80개 포인터, 세이브 슬롯 감지, 아이콘 값, 미믹 감지 및 쓰기 경로 전체를
업데이트/검증한 상태가 아니다.

## 진단 동작

`tools/diagnose_1171.py`는 표준 라이브러리만 사용한다.

1. 실행 중인 `eldenring.exe`가 하나인지 확인한다.
2. EXE 파일 버전을 기록한다. 타이틀 화면의 App/Regulation 버전과 동일하다고 가정하지 않는다.
   실제 사용자 보고서에서 파일 버전 2.7.1.0이 반환되어 기존 1.17.1 비교 차단을 제거했다.
   App/Regulation 1.17.1은 사용자가 제공한 화면 정보이며 도구가 독립적으로 확인한 값은 아니다.
3. 파일의 `.text`에서 GameDataMan 패턴이 정확히 한 번 나타나는지 확인하고
   RIP 상대 주소를 계산한다. 누락·중복·이미지 밖 주소는 실패한다.
4. `OpenProcess`에 QUERY_INFORMATION 및 VM_READ 권한만 요청한다.
5. 캐릭터의 무기·방어구·탈리스만 14칸, 능력치 9개, 마법 12칸을 읽는다.
6. 능력치 범위와 캡처 도중 캐릭터 포인터 변경 여부를 검사한다.
7. `compatibility-report.json`을 기록한다. 캐릭터 이름이나 Steam 계정 ID는 수집하지 않는다.

진단에는 메모리 쓰기, 원격 함수 실행, 게임 파일 패치, 오프셋 자동 적용이 없다.
읽기가 성공해도 장비 교체 성공이나 아이템 소유 검증을 의미하지 않는다.
보고서의 `write_support_verified`는 항상 false다.

## Windows 진단 EXE 제작 방식

사용자가 제공한 PyInstaller EXE의 Windows 부트로더·Python 3.13 런타임과 의존성을
재사용했다. 별도 파일 `Compatibility Check.exe`의 main 엔트리만 우리가 작성한
진단 코드로 교체했다. 원본 파일은 수정하지 않았고 애플리케이션 진입점도 실행하지 않았다.
제작 스크립트는 `tools/build_diagnostic.py`이며 입력 SHA-256과 아카이브 형식을 검사한다.
결과 EXE의 main 페이로드가 우리가 컴파일한 바이트코드와 동일한지 검증했다.

이는 Windows에서 실행해 본 빌드가 아니다. 이 Linux 환경에서는 Windows 네이티브
런타임과 실제 게임을 실행할 수 없어, 부팅/WinAPI 동작은 사용자의 PC에서 확인해야 한다.
문제가 나면 같은 ZIP 안의 Python 소스로 실행하거나 오류 내용을 참고할 수 있다.
제삼자 EXE/런타임은 Git 저장소에 포함하지 않는다. 재배포 권한이 확인된 것이 아니므로
이 사용자 제공 런타임 기반 결과물을 공개 릴리스로 게시하지 않는다.

## 사용자의 PC에서 필요한 검증

1. 배포 ZIP을 새 폴더에 압축 해제한다.
2. 1.17.1 오프라인 게임에서 캐릭터를 로드한다.
3. `Read-only Check.cmd`를 실행한다. Python 별도 설치는 진단 EXE 사용 시 필요하지 않다.
4. 생성된 `compatibility-report.json`을 전달한다. 오류가 나면 오류 화면 또는 파일을 전달한다.

이 보고서가 있어야 실제 읽기 성공 여부를 판단하고 장비 교체 연동 작업을 이어갈 수 있다.
이 ZIP은 1.17.1에서 검증된 완성 모드가 아니다.

키 설정은 원본 모드를 종료한 뒤 기존 `keyboard_hotkeys.json`을 백업하고,
제공한 파일을 EXE 옆에 복사해서 적용한다. 작업 디렉터리는 EXE 폴더여야 한다.
원본 UI에 프리셋 4개가 먼저 있어야 하고, 목록 순서 1~4번에 키가 연결된다.
원본 모드의 1.17.1 호환성을 확인하기 전에는 이 설정을 실제 장비 교체 검증의 근거로 삼지 않는다.
