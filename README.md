# Elden Ring Presets — Windows 테스트 빌드

Windows Steam판 엘든링 오프라인 장비 프리셋 앱입니다. 게임 App/Regulation **1.17.1**과
DLC를 대상으로 개발 중입니다. 사용자 PC에서 장비·능력치·마법·소지품 읽기를 확인했고,
**실제 장비 교체와 Windows 앱 실행은 아직 확인하지 못했습니다.** 완성 모드로 안내하지 않습니다.

## 현재 구현

| 기능 | 상태 |
| --- | --- |
| F1~F4 현재 장비 저장 | 구현, 파일 저장 로직 테스트 통과 |
| 숫자 1~4 프리셋 불러오기 | 게임 함수 호출 코드 구현, 실게임 미검증 |
| 무기 6칸·방어구 4칸·탈리스만 4칸 | 실제 읽기 및 인벤토리 대조 확인 |
| 소지한 장비만 선택 | 1,428개 실제 소지품에서 장비 14칸의 ID·개체·인덱스 대조 성공 |
| 강화·변질 및 같은 무기 여러 개 구분 | 정확한 ID 및 개체 handle로 선택, 테스트 통과 |
| 캐릭터 이름 + 사용자 지정 프로필별 저장 | 구현, 저장 로직 테스트 통과 |
| 능력치·레벨 복원 옵션 | 직접 쓰기 및 읽기 확인 코드 구현, 실게임 미검증, 기본 꺼짐 |
| 기억한 마법 복원 옵션 | 게임 함수 호출 코드 구현, 실게임 미검증, 기본 꺼짐 |
| Ctrl+F 프리셋 선택 메뉴 | UI 구현, Windows 미검증 |
| Xbox 패드 단축키 | XInput 구현, Windows 미검증 |

원본 Loadout Manager의 전체 기능을 재구현한 상태는 아닙니다. 소모품·화살·볼트·파우치,
아이템 아이콘/이름 데이터베이스, 스탯 편집, 미믹 전용 프리셋, 트레이 상주,
PlayStation 패드 지원, 원본의 모든 설정·가져오기/내보내기 기능은 남아 있습니다.
실게임 장비 교체를 먼저 확인한 뒤 범위를 확장해야 합니다.

## GitHub에서 실행 파일 받기

작업 브랜치에 푸시되면 `Windows build` 워크플로가 Windows에서 테스트와 빌드를 실행합니다.
GitHub 저장소의 **Actions → Windows build → 성공한 실행 → Artifacts →
EldenRingPresets-Windows-test-build**에서 ZIP을 내려받을 수 있습니다.
이 ZIP은 채팅 첨부 파일 서비스와 별개입니다. 실제 빌드가 성공했는지 먼저 확인해야 합니다.
Windows 빌드 성공도 실제 엘든링 장비 교체 검증을 의미하지는 않습니다.

## 실행 파일 만들기 — 원본 EXE를 가지고 있는 경우

이 저장소에는 원본 EXE나 제삼자 Python 런타임을 포함하지 않습니다.
사용자가 제공한 원본 Loadout Manager 1.3.5의 **런타임만 로컬에서 재사용**하여
독립된 테스트 앱 EXE를 만드는 도구를 제공합니다. 원본 애플리케이션 main은 새 앱의
코드로 교체한 별도 파일에만 적용되며, 원본 파일은 수정하지 않습니다.

채팅 첨부 다운로드가 작동하지 않는 경우에는 `release/Install-EldenRingPresets.ps1`을
텍스트로 열어 전체 내용을 복사한 뒤 Windows PowerShell에 붙여넣으면 됩니다.
이 파일 한 개에 앱 코드가 포함되어 있어 별도 ZIP·JSON·Python 설치가 필요 없습니다.

저장소 파일들을 이미 가지고 있다면 아래 명령으로도 같은 도구를 실행할 수 있습니다.

```powershell
& .\tools\install-from-original.ps1
```

파일 선택 창에서 기존 **Loadout Manager.exe**를 선택하면 바탕화면 `EldenRingPresets-Test` 폴더에 별도 EXE가 만들어집니다.

원본 파일의 SHA-256, Python 3.13 아카이브 형식, 새 코드의 SHA-256을 검사합니다.
원본 파일이 다르거나 형식이 맞지 않으면 만들지 않습니다. 기존 결과물도 덮어쓰지 않습니다.
이 경로 역시 Windows에서 직접 실행해 검증한 상태는 아닙니다.

## 일반 Windows 빌드

원본 EXE 없이 Windows x64 Python 3.13에서 독립적으로 빌드할 수 있습니다.
GitHub Actions `Windows build`도 같은 방식으로 실행 파일을 만듭니다.

```powershell
python -m unittest discover -s tests -p "test_*.py" -v
python -m pip install pyinstaller==6.16.0
python -m PyInstaller --clean --noconfirm --onefile --windowed --name EldenRingPresets --paths . app/main.py
```

결과: `dist/EldenRingPresets.exe`. Actions 빌드는 별도 Windows 검증 결과를 확인해야 합니다.

## 첫 실게임 확인

실제 교체 함수 호출은 아직 미검증이므로 게임 세이브를 먼저 백업한 뒤 테스트 캐릭터로 확인하세요.

1. 원본 Loadout Manager를 종료합니다. Easy Anti-Cheat가 비활성화된 오프라인 게임에서 캐릭터를 불러옵니다.
2. 테스트 앱을 실행하고 `게임 연결 / 새로 읽기` 결과를 확인합니다.
3. 처음에는 능력치·마법 옵션을 끈 상태로 F1을 눌러 저장합니다.
4. 게임에서 방어구 한 부위만 수동으로 바꾼 뒤 숫자 1을 눌러 복원되는지 확인합니다.
5. 정상 확인 뒤에 F2~F4, 무기, 탈리스만 교체를 확인합니다. 불일치 오류가 나면 추가 교체를 중단하고 로그를 확인합니다.

오류 로그와 프리셋: `%LOCALAPPDATA%\EldenRingPresets`.
단축키는 게임 창에 포커스가 있을 때 작동합니다. 숫자키의 원래 게임 입력을 차단하지 않습니다.
메뉴·텍스트 입력 중에는 앱의 단축키 체크를 꺼 주세요. 현재 메뉴 상태 자동 감지는 없습니다.
같은 이름의 캐릭터가 여러 개면 서로 다른 프로필 이름을 직접 지정해야 합니다.
다른 게임 실행 파일에서 저장한 프리셋은 불러오지 않으며, 게임 재실행 시 앱도 다시 실행해야 합니다.

## 장비 교체 방식과 한계

- 고정 주소만 믿지 않고 실행 파일의 유일한 패턴으로 GameDataMan 및 장비 함수를 찾습니다.
- 1.17.1을 지원한다고 명시한 TGA 커밋 `7926205c5a2ed236dd31278c4f5579c964ceec35`의
  장비/마법 호출 규약과 필드 위치를 참고했습니다.
- 현재 장비의 인벤토리 연결을 매번 검증하고, 저장 당시 handle이 있으면 우선 선택합니다.
- 소지품이 부족하면 장비 교체를 시작하지 않습니다. 보관함은 대상이 아닙니다. 아이템 생성 기능은 없습니다.
- 게임의 정상 장비 함수를 별도 스레드에서 호출합니다. 기존 장비 ID/handle 필드를 직접 덮어쓰지 않습니다.
- 탈리스만을 바꿀 때는 바뀔 슬롯을 먼저 해제하고 채워 임시 중복 충돌을 줄입니다.
- 교체 후 장비 ID와 handle을 다시 읽습니다. 실패 시 자동 롤백은 없고 일부 슬롯이 변경될 수 있습니다.
- 시간 초과된 함수가 실행 중일 수 있으므로 해당 코드 메모리를 해제하지 않고 추가 작업을 막습니다.
- 패턴 일치 및 읽기 성공은 쓰기 함수 안정성이나 DLC 동작을 보장하지 않습니다.
- Windows 파일 버전 2.7.1.0과 타이틀 화면 App Ver. 1.17.1을 혼동하지 않습니다.

## 개발 및 검증

Linux의 g++ 및 Python 3 표준 라이브러리만으로 코어 테스트를 실행할 수 있습니다.

```sh
./scripts/check.sh
```

C++ 코어 테스트와 Python 테스트를 실행합니다. 가짜 게임 브리지 테스트는 소지품 변경,
누락 장비, 탈리스만 순서, 장비 함수 인자, 읽기 불일치 후 중단 등을 검증합니다.
Windows GUI/WinAPI 및 실제 장비 교체를 테스트한 것은 아닙니다.

사용자 제공 런타임용 새 코드 payload를 갱신하려면 Python 3.13이 필요합니다.

```sh
/usr/bin/python3.13 tools/build_app_payload.py
```

`release/app-payload.json`에는 이 저장소의 코드만 들어갑니다. 원본 모드/런타임은 들어가지 않습니다.
개인 진단 보고서와 장비 데이터는 Git에 포함하지 않습니다.
기존 `include/`, `src/`는 별도 C++ 실험 코어이며 Windows 앱 실행 경로는 `app/`입니다.
